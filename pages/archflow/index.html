Die Architektur von MyWorkLog

Diese Karte zeigt den Quellcode der App: jede Datei ist eine Kachel, jede Linie eine Ladebeziehung. Wenn eine Seite ein Skript einbindet oder ein Stylesheet nachlädt, steht diese Linie hier.

Wie man sie liest

Die Farbe bedeutet genau eine Sache — die Art der Datei:

  • Seiten und Vorlagen (HTML)
  • Programmcode (JavaScript)
  • Gestaltung (CSS)
  • Konfiguration und Daten (JSON)

Eine Verbindungslinie trägt die Farbe dessen, was sie lädt. Die Rahmen fassen zusammen, was fachlich zusammengehört — Dashboard, Historie, Berichtsheft und so weiter.

Bedienung

Ziehen verschiebt, Scrollen zoomt. In der Übersicht bleiben die Namen aus, weil sie dort nur wenige Pixel hoch wären; hineinzoomen bringt sie zurück. Ein Klick auf eine Kachel zeigt, was sie lädt und wer sie lädt.

  • /Suche
  • 0alles einpassen
  • +−Zoom
  • Escschließen

Woher die Daten kommen

Die Karte ist nicht von Hand gepflegt. Ein Analyse-Werkzeug liest das Repository ein, verfolgt die Verweise zwischen den Dateien und schreibt das Ergebnis in eine Datei, die diese Seite lädt. Sie zeigt also den Stand des letzten Durchlaufs, nicht eine gezeichnete Wunschvorstellung.

Der Quellcode von MyWorkLog ist offen. Was hier als Kachel steht, kannst du dort als Datei nachlesen — die Karte ist der Überblick, das Repository die Wahrheit.
